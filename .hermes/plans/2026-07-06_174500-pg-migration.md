# SQLite → PostgreSQL Migration Plan (v2)

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Migrate the Hegre review database from SQLite (NAS-mounted, lock-prone) to PostgreSQL 192.168.86.49 with Alembic migrations and pgvector. Single authority — no dual-backend fallback. `review.db` is renamed to `review.db.old` so any stale code that tries to open it fails loudly instead of silently degrading to a stale copy.

**Architecture:** SQLAlchemy ORM → Alembic migrations → one-shot export/import/verify → `HegreDataset.db`/`db_writable` swapped to SQLAlchemy engine pool → old sqlite3 code deleted. Connection string lives in `config/database.yml`. All tables (personas, sets, images) and all columns (including `auraface_embedding VECTOR(512)`) are in the initial migration.

**Tech Stack:** SQLAlchemy 2.x, Alembic, psycopg2, pgvector, pytest.

**Branch:** `exp/pg-migration` (from `exp/text-to-zg`).

## Design Summary

### Target PostgreSQL Schema

```sql
personas (id SERIAL PK, name TEXT UNIQUE NOT NULL)

sets     (id SERIAL PK, persona_id INT NOT NULL REFERENCES personas(id),
          slug TEXT NOT NULL, UNIQUE(persona_id, slug))

images   (id SERIAL PK,
          persona_id INT NOT NULL REFERENCES personas(id),
          set_id INT NOT NULL REFERENCES sets(id),
          image_path TEXT NOT NULL,
          source_image TEXT NOT NULL,
          face_index INT DEFAULT 1,
          status TEXT DEFAULT 'unreviewed',
          reviewed_at TIMESTAMPTZ,
          zg_distance DOUBLE PRECISION,
          af_distance DOUBLE PRECISION,
          auraface_embedding VECTOR(512),
          UNIQUE(persona_id, set_id, source_image, face_index))

CREATE INDEX idx_images_status ON images(status);
CREATE INDEX idx_images_persona ON images(persona_id);
```

### Config

```yaml
# config/database.yml
development:
  url: postgresql+psycopg2://tim@192.168.86.49/eidolon
  pool_size: 5
  max_overflow: 10
```

### HegreDataset — PostgreSQL Only

```python
class HegreDataset:
    def __init__(self, root: Path):
        self.root = Path(root).resolve()
        self._engine = create_engine(DATABASE_URL, pool_size=5, max_overflow=10)
        self._personas: dict[str, Persona] | None = None

    @property
    def db(self):
        return self._engine.connect()  # PG handles reads

    @property
    def db_writable(self):
        return self._engine.connect()  # PG handles concurrent writes natively
```

### Loud-Failure Guard

```python
# tools/hegre_dataset/dataset.py — at import time
if (Path(self.root) / "review.db").exists():

        "review.db still exists at dataset root. "

    )
```

import yaml

## Risks

1. **Single point of failure:** PG down = everything down. Acceptable tradeoff — the NAS SQLite was also a single point of failure.

2. **Network latency:** PG queries go over LAN instead of local filesystem. Mitigated by connection pooling.

3. **SQL dialect differences:** `datetime('now')` → `NOW()`, `CAST(x AS REAL)` → `x::float`. Export script handles conversion.

4. **Alembic for schema only, not data:** Data migration is a one-shot script, not a versioned Alembic migration.

5. **`review.db.old` remains on disk:** It's a safety net. Can be archived/deleted after a week of verified PG operation.
